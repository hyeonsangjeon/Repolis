## 3. 통합 시놉시스 — 「귀향, 그리고 안내자의 계절」

> **로그라인**: 당신이 몇 년 동안 push한 커밋이, 모르는 사이에 도시 하나를 지어 놓았다. 오늘 처음 그 도시에 돌아오고, 마을은 안내를 자기 일로 삼기로 한다.

세계관(별 이름 현자, 월드 트리, 깃버 택시, 다섯 현자가 각자 하나의 지식원만 믿는 것, 세계수는 말하지 않고 장부만 남기는 것)은 그대로 둔다. 바꾸는 것은 **시점**(관광객 → 귀향자)과 **순서**(기능 목록 → 길 하나)다.

### 두 시놉시스를 합치며 바꾼 다섯 가지

1. **첫 질문은 두 박자다.** 「귀향」은 "GitHub 아이디"를, 「안내자의 계절」은 "무엇을 하러 왔나요?"를 첫 질문으로 뒀다. 의도만 물으면 남의 마을에서 고르는 관광이고, 아이디만 받으면 내 도시에서 길을 잃는다. 그래서 **아이디(모를 때만) → 의도** 순서로 묻는다. `?user=`·`?repo=` 링크로 온 사람은 아이디가 이미 있으니 의도만 묻는다. 주인 마을을 샘플로 보는 사람도 의도만 묻는다.
2. **투어의 화자가 바뀐다.** 「귀향」은 깃버 혼자 3정거장을 안내했다. 「안내자의 계절」은 구역마다 주민 안내자를 뒀다. 합치면 **정거장은 데이터가 고르고(가장 높은 집·가장 오래된 집·의외의 집), 각 정거장에서 말하는 사람은 그 구역의 주민 안내자**다. 깃버는 운전만 한다. "주민이 전문 질문을 현자에게 넘긴다"는 기존 원칙과도 맞는다.
3. **세 갈래 길 = 세 의도.** 길찾기의 기존 의도 세 개(레포 하나 이해하기 · 이 개발자의 도시 둘러보기 · 기여할 일 찾기)를 그대로 **이해의 길 · 탐방의 길 · 기여의 길**로 부른다. 「귀향」의 3정거장은 *탐방의 길*의 구현이고, 이해의 길은 전시실 직행, 기여의 길은 퀘스트 결과를 들고 실제 집 앞까지 가는 것이다. 새 공간은 짓지 않는다.
4. **흔적은 하나만 권한다.** 「귀향」은 도시 카드를 자동으로 띄웠고, 「안내자의 계절」은 길·장면·연결 중 하나만 권했다. **하나만 권한다는 원칙을 채택**하되, 어느 하나를 권할지는 걸어온 길이 정한다. 탐방의 길 → 도시 카드(기본값), 이해의 길 → 전시실 링크 또는 Repo Route, 기여의 길 → 이슈를 들고 GitHub로(기존 Star 초대 포함).
5. **발견은 메뉴에 없다 = 단계적 해금.** 「안내자의 계절」의 "엘더의 한마디, 뿌리 아래 서고, 밤하늘 별자리는 걷는 사람만 만난다"와 「귀향」의 "도장마다 기능 하나 해금"은 같은 원칙이다. 공유 도구는 집 2채를 연 뒤(B)에, 블루프린트·퀘스트는 도장 수(A)에 따라 펼친다.

### 4막 구조

**0막 · 도착 전** — 링크가 곧 초대장. `?user=<login>` 링크의 미리보기가 *그 사람 도시 카드*다. 카드를 받은 사람은 1막부터 반복한다.

**1막 · 도착 (0~30초)** — "당신의 커밋이 지은 도시"
- 첫 화면은 질문 하나: **"GitHub 아이디를 넣으면, 당신의 도시를 지어 드릴게요."** 아래 작게 "먼저 샘플 도시 보기(주인 마을) · 가이드 투어".
- 입력 → 역(🚉)에서 깃버가 손 흔듦 → **건설 타임랩스**(기존 Town Growth Replay 자동 재생, 12~30초, reduced-motion이면 정지 프레임): 첫 레포 집부터 연도순으로 솟아오른다. 캡션 "2019 — 첫 집 youtube-dl-nas".
- 마지막 프레임에 **도시 이름 명패**(예: "Port Hyeonsang — Python 항구 도시"). 이름은 언어·토픽 비율로 결정적 생성. 뒤에서는 이미 마을이 살아 움직인다(B).
- 그리고 한 문장: **"무엇을 하러 왔나요?"** — 이해 · 탐방 · 기여.

**2막 · 안내 (30초~5분)** — "길마다 안내자가 붙는다"
- **이해의 길**: 집 문을 열고 원문(README)과 소스 지도를 보여준다. 전시실은 이미 완성도가 높다. 문제는 거기까지 *가는* 사람이 없던 것이다.
- **탐방의 길**: 깃버 택시 + 구역 안내자 셋. 정거장은 데이터가 고른다.
  1. **가장 높은 집** — 안내자: "이 집이 제일 높은 건 순방문자 2,113명 때문이에요." (건물 규칙을 경험으로 가르침)
  2. **가장 오래된 집 또는 가장 조용한 집** — "2019년부터 여기 살았어요. 요즘은 조용하죠." (Silence Ledger를 사람 대사로 번역)
  3. **의외의 집** — 토픽이 외딴 집, 포크 출처가 있는 집, ★0인데 최근 push된 집("아무도 모르지만 당신은 아직 돌보고 있는 집"). 여기가 "이런 것도 되네"의 자리.
- **기여의 길**: 열린 이슈 세 장을 들고 실제 집 앞까지 간다(기존 퀘스트). 같은 레포의 블루프린트가 있으면 Issue-to-Code Scout가 파일 후보를 보여준다.
- 어느 길이든 끝나면 **여권에 도장 3개**. 이때 처음으로 나머지 기능이 "열림" 애니메이션과 함께 해금된다.

**3막 · 흔적 (5~10분)** — "하나만 권한다"
- 마을이 묻는다: 이 길을 친구에게 넘길지, 장면을 남길지, 네 마을과 이을지. **길이 정한 하나만** 크게, 나머지는 작게.
- 탐방의 길의 기본값은 **도시 카드**(1280×640: 스카이라인 실루엣 + 도시 이름 + 레포 수·★·주 언어·대표 집 3채). 버튼 두 개: **복사 / GitHub 프로필에 붙이기**.
- 발견은 메뉴에 없다. 엘더의 한마디, 뿌리 아래 서고(Undercroft), 밤하늘 별자리는 걷는 사람만 만난다.

**4막 · 귀환 (다음 방문)** — "지난번보다 집 2채 늘었어요"
- Town Gazette는 이미 `?user=` 마을을 지원한다(브라우저당 5개 마을 스냅샷). 재방문자는 의도 카드 대신 Gazette 배너를 먼저 본다.
- 오늘 push가 있으면 축제등, 7일 없으면 안개. 재방문 이유가 된다.

주인(hyeonsangjeon) 마을은 사라지지 않는다. **🚉 역의 기본 노선 중 하나**이자, 2막 끝에 깃버가 "이 엔진을 만든 사람의 도시도 가 볼래요?"라고 권하는 *샘플 도시*가 된다. 기존 `?view=plaza&lang=en` 캠페인 링크는 그대로 동작한다.

## 5. 발굴한 아이디어 목록 (우선순위)

점수: **임팩트**(아하 강도) × **난이도 역수**. ★★★ = v1.96~1.97, ★★ = v1.98, ★ = v2.0.

### ★★★ 즉시 — 핫픽스와 구조 수술 (AI 불필요, 서버·새 요청 없음)

1. **깃버 자연어 커버리지** (B) — `\bstars?\b`→`\bstar(s|red)?\b`, `\brecent(ly)?\b`, 랜덤 의도에 `anything`·`아무거나`, 한글 음차 사전(도커·쿠버네티스·레디스·장고·리액트…), 이름 토큰 `ai` 단독 매칭 패널티(A), 결과에 ★·최근 push 가중(A), **실패 시 제안 칩 3개**(B). 위 표의 질의 전부를 `scripts/test-gitber-search.mjs`에 넣는다.
2. **모바일 마감** (B) — '마을 · 방문' 드롭다운을 배지 밖으로(또는 `backdrop-filter` 제거), 전시실 퇴장 후 카드 층위, 힌트 바를 토스트로, 세계수 버튼 레이블.
3. **"폐허" 워딩 교체 ×2** (A+B) — `ruinStatus`와 구역명 "실험·폐허 지구". 제안: "기념관 / 오래된 집", 구역은 "실험·기록 지구"(EN: archive district).
4. **README 서버 명령** (A+B) — `python3 -m http.server 8000 --protocol HTTP/1.1` (Python 3.11+). AGENTS.md·README.ko.md·repolis.yaml의 같은 줄도 함께.
5. **S0 랜딩 역전** (A) — username 입력을 1순위 CTA로. 문구: KO "GitHub 아이디 하나면, 당신의 레포들이 도시가 됩니다." / EN "Type a GitHub login. Your repos become a city you can walk."
6. **S1 건설 타임랩스 자동 재생** (A) — Growth Replay는 이미 있다. 입장 커버 뒤에서 자동으로 한 번.
7. **S2·S3 의도 질문 + 데이터 기반 3정거장 + 구역 안내자** (A+B) — 고정 코스(월드 트리→주민→레포→크로노폴리스→여권)를 *그 사람 데이터*가 고르는 3곳으로. 화자는 구역 주민.

### ★★ 다음 — 공유 루프와 검색 품질

11. **도시 카드 + 동적 OG 이미지** (A) — `?user=<login>` 링크의 미리보기가 그 사람 도시여야 바이럴이 된다. Cloudflare Worker에서 SVG 합성 → PNG(`resvg-wasm`류), 24h KV 캐시, 공개 메타데이터만. GitHub Pages는 정적이라 HTML `og:image`를 바꿀 수 없으므로 **카드 공유 링크는 Worker 도메인이 302로 Pages를 가리키는 구조**가 필요하다. 이 문서에서 ROI가 가장 높은 기술 항목.
12. **의미 검색** (A) — Worker에서 `text-embedding-3-large`로 레포 설명 벡터를 **빌드 시 1회** 계산해 `data/embeddings.json`으로 저장, 클라이언트는 코사인만. 런타임 비용 0, 키 불필요.
13. **GitHub 프로필 포털의 매일 갱신** (A) — 포털 이미지가 Worker 카드를 가리키면 README 속에서 **매일 조금씩 바뀌는 살아있는 도시**가 된다. 외부 유입 채널.
14. **유명 개발자 도시 갤러리** (A) — `mrdoob`, `torvalds`, `gaearon`, `karpathy` … 20~50명을 사전 렌더 카드와 함께 `/gallery.html`로. SEO 랜딩이자 "이런 것도 되네"의 데모.
15. **여권 여정 페이지** (B) — 어느 길을 걸었고 어디서 멈췄는지 한 장.

### ★ 그 다음 — Foundry로 "도시가 말한다"

비용은 걱정하지 않되 **Worker 뒤에서만, 공개 메타데이터만, 캐시 필수**(기존 Entra·budget governor 원칙 유지).
